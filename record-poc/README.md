# DAC 対戦記録 PoC

既存Viewerを変更しない、スマホ向けの記録PoCです。記録・メモなどは端末内に保存します。外部ライブラリは使用しません。

## 起動

リポジトリのルートで `node tools\serve.js` を実行し、PCで
`http://localhost:8080/record-poc/index.html` を開きます。既存の開発サーバーは存在しないファイルを外部サイトから取得する仕様ですが、本PoCの全資源はローカルにあります。

スマホで試す場合は、このフォルダーをHTTPSの静的ホスティングに配置してください。
公開してよいのはアプリのファイルだけで、個人の対戦記録やバックアップを配置しないでください。
同じWi-FiのPCのIPアドレス経由でも通常画面を確認できますが、HTTPSでない場合は
Service Workerによるオフライン起動が利用できません。ファイアウォールの設定変更・公開配信は自動では行いません。

iPhone / Androidの実機で貼り付け、ファイル保存、リロード復元を確認してください。
対応ブラウザではホーム画面追加が可能です。インストール可否やアイコンの扱いはOS依存です。

## 操作

### Excel抽出設定の利用

#### ８種類のマスター

「設定・バックアップ」の「ファイル追加」からVBAのJSONを追加します。
１ファイルずつ繰り返し追加することも、まとめて選ぶこともできます。追加済みファイルの種類は
JSON内部の `masterType` で自動選択され、不要な種類はチェックを外せます。拡張子は `.json` を使用してください。
画面と出力名は次の番号順です。VBAは番号付きの名前を優先し、従来名も読み込めます。
基準フォルダーではこの対応名が必要なので、任意の名前への変更はアプリ取込用のコピーだけにしてください。

| 画面 | 出力ファイル |
| --- | --- |
| 01_店舗 | `01_STORE_Master.json` |
| 02_自分用チーム | `02_TEAM_Master.json` |
| 03_カード | `03_CARD_Master.json` |
| 04_対戦履歴 | `04_OPPONENT_Master.json` |
| 05_ラウンド設定 | `05_ROUND_Master.json` |
| 06_車種 | `06_CAR_Master.json` |
| 07_ランク | `07_RANK_Master.json` |
| 08_エリア | `08_AREA_Master.json` |
| 09_コード | `09_CODE_Master.json` |

コードの内部種類名は既存データ互換のため `CORD_Master` のままです。

「日次更新」は店舗・自分用チーム・カード・対戦履歴、「全数更新」は全項目をチェックします。
これらのボタンはチェックを変更するだけで、保存内容は変更しません。
初回は `AREA_Master`、`CAR_Master`、`ROUND_Master`、`STORE_Master`、`TEAM_Master`、
`CARD_Master`、`RANK_Master`、`CORD_Master` の設定マスターがすべて必要です。
対戦履歴が不要ならチェックを外せます。初回後は必要な項目だけ更新できます。

追加済みファイルの種類が選択され、チェックを入れた種類だけが対象です。
選択状況とファイル内の件数は「1 取り込む内容」の各項目に表示します。
対象種類の不足・重複があれば内容確認を保留します。
各項目の「外す」でファイルを除けます。重複時はファイル名別のボタンで不要なものを外してください。
「内容確認」を押すと、04の項目に正式記録の追加・修正・削除・正式登録移行件数を表示します。カード差分がある場合は「カード差分」を展開して確認できます。確認に失敗した場合は理由が表示されます。
「内容反映」で１回の端末内保存に反映し、「取込中止」で確認を取り消せます。
Excelを正本とし、選択した種類のマスターはJSONで置き換えます。JSONにない旧定義・正式記録は削除し、選択していない種類は変更しません。
`04_OPPONENT_Master`は同じData_No.の修正を反映します。アプリの新規記録は、入力途中の下書き・貼り付け内容とともに保持します。
JSONの正式記録と仮登録の仮No.が一意に完全一致した場合だけ、同じ対戦としてExcelの内容で正式登録へ移行します。
仮No.がない・一致しない仮登録を、日付・名前等の推測で削除することはありません。重複ID・仮No.があるJSONは反映しません。
空の対戦履歴マスターは正式記録を全削除しますが、仮登録は保持します。出力するJSONの範囲が、そのままアプリで保持する正式記録の範囲です。
未選択のマスターを参照する定義が不足する場合は、関連マスターを一緒に選択してください。参照エラーは部分反映せず停止します。

ラウンド開始などは、変更した設定だけにチェックしてください。
不変のマスターを再生成・再登録する必要はありません。Excelの「一括生成」は設定8種類と
対戦履歴（04）の全9種類を出力します。そのフォルダーの設定JSONを
日次・タイミング更新マクロの基準にしてください。対戦履歴だけ更新する場合は、
「個別生成」で「04: OPPONENT_Master」を選ぶか、「OPPONENT_Master生成」ボタンで04だけを出力できます。
各更新フォルダーには未選択の前回の設定マスターも
同梱されるため、次回の基準として利用できます。

反映前に、同じIDのカードに差分があれば変更前後を表示します。常にExcel側を採用し、採用先の選択は不要です。
カード名・チーム・現在ランク・★・登録車両・車庫が対象です。
オンライン対象値もJSONの値で置き換えますが、カードの選択には使用しません。
カード表のランク・★が両方空欄の場合、Excel側は未登録として表示します。
選択後に「内容反映」を押すまで保存しません。プレビュー中に設定を変更した場合は
ファイルを選択し直してください。対戦下書き、未適用の設定編集は保持されます。

STOREはAREA、CARDはCAR・TEAMを参照します。個別取込では既存設定と合わせて参照を確認し、
不足している場合は不足するマスターを表示して反映を保留します。８種類の一括取込では全ファイルを
統合してから検証し、１回の端末内保存で反映します。不正なファイルや保存失敗では部分反映しません。
不足マスターを先に取り込むか、必要な種類もチェックしてファイルを追加してください。
TEAMの所属店舗名は店舗マスターとの一致を要求しません。対応する店舗IDがない場合はIDを空にし、
店舗名を保持します。取り込んだ種類の古い車種・コース・シーズン・エリア・店舗・チーム・カードと、それらの追加候補は残しません。
過去記録や下書きの文字列は参照先の削除で書き換えず、候補外の値として保持します。

- 画面上部のカード選択は「２．カード情報」のカードと連動し、選択したカードで対戦を記録します。ランク・星は今回の入力値を表示し、編集は「２．カード情報」で行います。項目名は画面には表示しません。
- ★は４個ごとに間隔を空け、幅が足りない場合は４個単位で折り返して中央揃えにします。表示用の間隔を保存値やCSVに追加しません。PRIDEの数値はそのまま表示します。
- ヘッダーの色はCARDマスターの順に緑・水色・赤・青・黄色を繰り返します。カード未選択やマスターの候補外は緑です。
- カード候補はCARDリストの全カードです。選択するとカード別の現在ランク・星を反映し、カードのある行の下に自チームとチーム番号・所属店舗を表示します。未保存のスロット変更がある状態でカードを切り替えると、破棄するか確認します。
- 自チームはリストで変更でき、選択したカードの現在設定として端末に保存します。過去の対戦記録や相手チームは変更せず、次回CARDマスター取込時はExcelの設定で置き換えます。
- 自車種はカードの登録スロット最大3台。相手車種はメーカーを選択し、そのメーカーの車種から選びます。
  前回車種がある場合は対応するメーカーを自動選択します。メーカーを変更すると相手車種の入力は空になります。
  メーカー不明の車種は「メーカー未分類」に表示し、車種の直接入力もできます。
- メーカーは車種リストの `--- TOYOTA ---` のような見出し、車種の `manufacturer` 属性、
  それらのない旧設定では2026-11-15のExcelと照合した既存車種IDを使用します。
  旧設定に追加された車種は推測せず未分類とします。
- 相手名欄の下に、04マスターのExcel基準の勝率と端末内の前回対戦日を表示します。
- カードのスロット／車庫の車種候補は、Excelの車種シートの区切り位置を
  `common.vehicleDividers`（直後の車種ID・元の区切り文字列・出典）で保持します。
  区切り文字だけの場合は `---------------------`、`--- TOYOTA ---` などメーカー名付きの場合はその見出しを、
  それぞれ選択不可として表示します。メーカー名は推測しません。
  登録3台だけの自車種候補には区切りを挿入しません。
- ラウンド候補は選択シーズンの開催設定、コース候補はそのラウンドの対象コースです。
- 「入力」→「１．ラウンド情報」→「ラウンド別の対象コースを確認」で保存済みの対応表を確認できます。
  設定は端末内IndexedDBの `settings.catalog.common.rounds[].courseIds` に保存され、
  `settings.catalog.common.courses` のコースIDを参照します。設定JSON再取込で更新できます。
  マスター利用時はコースの直接入力を出さず、対象ラウンドのコースだけ選択できます。
  候補外の前回値は消去せず選択不可の表示として残し、警告に従って選び直します。
- エリア・店舗は抽出リストと既存の追加候補を利用します。
- 対戦入力のチームは相手の所属情報です。候補は過去記録の「チーム＋チーム所属店舗」の組から作り、
  チーム欄へ1文字以上入力すると直下に候補を表示します。候補選択で所属店舗も一緒に反映します。
  PCでは上下キーで候補へ移動し、Enterで選択、Escapeで閉じられます。候補がない名前もそのまま入力できます。
  同じチームの別店舗もそのチームの履歴から選択できます。
  組の候補をクリックすると両方を反映し、今回と違う場合は直接入力で修正できます。
- カード表から抽出した自分用チームは、対戦相手の候補には追加しません。既に混入した自分用リスト候補を
  初回起動時に除去しますが、対戦記録と下書きは保持し、相手履歴に実際にある同名チームは候補に残ります。
- ランク名・星は抽出リスト、ブレフラ等は意味を表示し既存コードを保存します。
- 候補外の前回値は勝手に置換せず、保持して警告します。カード切替時は前カードのランクを引き継がず、
  登録車両にない自車種を解除します。
- 新規入力は前カードを保持し、その現在ランクを反映します。日付に対応する開催設定が1件なら
  シーズン・ラウンドを補完します。マスター反映直後も未保存の下書きの未入力欄を補完し、
  入力済みの選択・その他の入力内容・保存済み記録は変更しません。

対戦後は実機の状態に自ランク・星を修正し「表示中の自ランク・星をカード設定に保存」を押すと、
次のカード選択・新規入力に使われます。勝敗からのランク自動計算や、過去記録による現在状態の上書きはしません。
カード名・チームのリスト・車両などの登録はマスター側で行います。
以前の未適用の設定編集はバックアップに残りますが、現在の画面からは適用できません。
車庫は登録済みの車種だけを連番で表示し、Excel由来の途中の空き行は起動時・設定取込時に詰めます。
スロット1～3の空き位置は保持します。
車庫・所属チーム・ランク比較値・詳細属性も設定内に保持し、バックアップに含めます。
カードの所属は `teamId` で自分用チームの組を参照します。
入力画面で登録カードを選ぶと、スロット1～3が横1行に並びます。各スロットの選択リストには車庫の車種が先に並び、リスト内の「その他車種」を開くと車庫にない全登録車種から選べます。
「未登録」で空欄にでき、3枠を編集してから「スロット変更を保存」で一括保存します。同じ車種を複数枠へは保存できません。
保存先は端末内のカード設定で、JSONバックアップに含まれます。対戦用CSVにはスロット構成は出力されません。
「スロットCSV出力」は、表示中のカードの保存済み車種だけを、スロット1～3の順に見出しなしの1列3行で出力します。空き枠は「未登録」です。ExcelでCSVを開き、3セルをカード表の該当カード列・13～15行に「値」として貼り付けます。未保存の変更がある間は出力できません。
`03_CARD_Master` を再取込するとExcel側のスロット構成に置き換わるので、アプリの変更を残す場合は先にExcelのカード表へ転記してください。
カード番号は取得・表示・保存・出力しません。Excelのカード表7行目は変更不要で、マクロは読み取りません。
旧マスター・設定JSON・バックアップに含まれるカードの `number` は取り込み時に除去し、
保存済み設定と旧カード編集下書きも起動時に番号を除去して保存し直します。カード名・内部ID・チーム番号は保持します。
タイミング更新でカードマスターを引き継ぐ場合も番号を除去します。過去に書き出したJSONやバックアップは自動更新されないため、別途削除・番号除去が必要です。
既存JSONは `node tools\master-export\remove-card-numbers.js "対象ファイル.json"` で
カード番号だけを除去して上書きできます（リポジトリルートで実行、複数ファイル可）。
番号入りのバックアップは作成しません。Excel元データやクラウドの版履歴は変更しません。
チーム番号はカード表の作成Teamリスト（AE列）から取り込み、未収録の古い設定では「未登録」と表示します。
ラウンド別の対象コース確認はシーズン・ラウンド選択後、その1件の開催期間と対象コースだけを表示します。
相手チーム一覧は保存済み対戦からチームと所属店舗の組を表で表示し、
チーム名・店舗名で絞り込めます。従来のフラットな設定値は互換性のため保持します。
折りたたみ欄の展開内容は1remインデントし、入れ子の欄も段階的に字下げします。
未定義コード0は意味を推測せずそのまま表示します。属性のバージョン履歴やランク差の自動計算は未実装です。

マスター更新はExcelで変更後、該当するマスターJSONを再出力・再取込します。
読み込んだ種類の共通マスターはJSONの全内容で置き換えます。

項目名と入力欄はスマホでも横に並べます。日付・シーズン・ラウンド、カード・自ランク・星数は各1行です。自車種は1行、相手車種はメーカーと車種の選択欄を含む1行で表示します。
項目名の列は折り返しを許容して狭くし、入力欄を広くしています。
対戦相手の上は3列×2行で、日付・シーズン・ラウンド／カード・自ランク・星数を配置します。
自ランクと星数はプルダウンです。星数は★1～8個から選択し、PRIDEの数値などは「直接入力…」で入力できます。
★表示は4個目と5個目の間へ半角スペースを入れます（例：★★★★ ★★★）。
自分・相手の星、星候補、カードの現在ランクで共通の表示にし、元の記録・設定の値は表示のためだけに書き換えません。
星の入力・登録ではこの表示用スペースを除き、PRIDEの数値は変更しません。
上部はスマホでも3列を維持し、狭い画面では項目名を入力欄の上に配置します。
入力画面は「１．ラウンド情報」「２．カード情報」「３．対戦情報」「４．対戦実績」に分け、本文をインデントします。
ラウンド情報は日付・シーズン・ラウンドを1行、カード情報はカード・自ランク・星数の1行と自チームの1行に配置します。
シーズン・ラウンド・カードは設定リストのプルダウンで、リスト外は「直接入力…」から入力できます。
新規入力の見出しは表示しません。起動時・設定取込時・新規入力時・日付変更時に、日付と開催期間から
ラウンドを一意に特定できれば未入力のシーズン・ラウンドを補完します。
選択済みラウンドの開催期間から日付が外れている場合も、該当するラウンドへ更新します。
起動時や設定取込時に保存済み対戦の訂正内容を自動変更することはありません。
店舗・チーム所属店舗・コース・双方の車種は設定リストのプルダウンです。チーム名は直接入力＋検索候補です。
未登録の通知欄は表示しません。「直接入力…」を選ぶとリスト外の値を入力できます。
過去情報にしかない値もプルダウンの選択肢に保持します。
ラウンド情報・カード情報は項目名と入力欄を揃えて枠で区切り、スマホ幅でも3項目を1行に配置します。狭い画面では選択欄の値が一部見切れる場合があります。
対戦入力は横2列の画面で、対戦相手／CN追加メモ、所属情報の折りたたみ欄（初期状態は閉じ、相手選択・貼り付け時にも自動展開しません）、
相手名の下の勝率／前回対戦日、相手ランク／★・PRIDE、チーム／チーム所属店舗、
コースと「選択権」「夜」「ランダム」、自車種、相手車種、対戦店舗エリア／対戦店舗、
ブレフラ・譲り／追加メモ、横幅いっぱいの「勝ち」ボタンの順に配置します。
コースを別の値に変更すると、選択権・夜・ランダムは未選択に戻ります。同じ値のままでは変更しません。
「勝ち」は押すたびに選択／非選択を切り替え、選択時はボタンと対戦相手から追加メモまでの入力欄全体を青背景にします。コース入力自体の前回勝敗色は保持します。
勝ちの下の前回結果案内は表示しません（前回対戦日・履歴は引き続き表示）。
夜・ランダム・選択権ありはチェックボックスです。これらと勝ちは選択時に文字列 `"1"`、未選択時は `"0"` で保存します。
選択権・夜・ランダムはボタン全体を押して切り替えられ、選択中はチェックと背景色で示します。狭い画面ではコースの下に並べます。
「勝ち」未選択は負けです。初期表示や過去照合で既存の未入力値を即時変換はせず、
対戦保存時に4項目をチェック状態へ揃えます。過去記録の表示だけでは値を変更しません。
「所属店舗／エリア」「対戦店舗／エリア」「チーム／所属店舗」の項目名は2行で表示します。
対戦店舗エリアが未入力のとき、選択画面は愛知県付近から表示します。エリアは実際に選ぶまで未入力のままです。チーム候補の「（チーム無所属）」を選ぶと、チーム欄にその文字列を保存し、チーム所属店舗は空欄にします。
所属情報の横2列表示では、エリア側を13.5remに抑え、残りの幅を所属店舗側に割り当てます。狭い画面では従来どおり縦に並べます。

### Excelから対戦履歴マスターを抽出

`tools\export_record_poc.ps1` に `-InputPath`（Excel）、`-OutputPath`（JSON）、
`-Count 300` を渡すとDシートの10行目以降から末尾300戦を抽出します。
出力は`OPPONENT_Master`なので、読み込むと正式記録はこの300戦だけに置き換わります。全件が必要なら十分大きいCountを指定してください（最大100000）。
この変換は2026-11-17更新の列配置（D～X、AC～AF、AW～AX、BA～BC）を使い、9行目の主要見出しを検査します。
`O列=R` と `Q列=夜` は `1`、`R列`の空欄は負けを表す `0` に正規化します。X列の仮No.も出力します。
元データ上の `AC`（Data_No.）と `BA`（カード）は必須で、ID重複はエラーにします。
相手名が空欄の対戦は `相手不明 (Data_No. 818)` のようにData_No.付きの一意な仮名を設定し、行番号とData_No.を警告表示して記録自体は保持します。この仮名は実在の相手名ではないため、実相手との履歴照合には使われません。
数式の再計算は行いません。Excelで計算・保存済みのファイルを使用してください。
元ファイルは読み取り専用で開きます。出力JSONは個人の記録なのでリポジトリには配置しないでください。

「設定・バックアップ」のマスター登録、または「対戦履歴JSONを読み込む」で取り込みます。
`OPPONENT_Master`は正式記録を置き換え、仮No.が一致した仮登録を正式登録へ移行します。下書きと未反映の仮登録は保持します。
`masterType`のない旧過去記録JSONやCSV v1は従来の追加方式です。通常のExcel往復には対戦履歴マスターを使用してください。
Excel由来の旧状態は互換性のため保持しますが、画面では区別しません。

対戦店舗・エリアは主画面、所属店・所属エリアは補足欄に配置しています。
エリアはプルダウン、店舗はエリア別候補選択と直接入力に対応します。
店舗候補はマスターと既存の設定から利用します。エリアを変更すると対応する店舗欄をクリアします。

従来のバックアップ（エリア別店舗リストなし）も復元できます。

## 保存・制約

期間指定のExcel貼り付け用CSVは「設定・バックアップ」→「２．バックアップ」の「Excel貼り付け用CSV」にあり、開始日・終了日を横1行に配置します。
入力画面の保存ボタン右下の「CSV出力」は、確認ダイアログなしでExcel未反映の保存済み記録を全件出力します。「２．保存」の期間指定は使わず、入力途中は含めません。端末内の保存完了を待ち、保存失敗時は出力を止めてエラーを表示します。
CSV出力で記録は削除せず、Excelへ転記済みとも扱いません。保存先指定・定期自動出力は未実装です。
それ以外のバックアップは「設定・バックアップ」画面の「２．バックアップ」で操作します。
同画面の「１．マスター登録」は「（１）取り込む内容」と「（２）ファイル取込」に分けて表示します。

- Excel貼り付け用CSV：2026-11-17更新のＤシートA～Y列と同じ25列を出力します。
  アプリ形式の対戦IDで保存された記録（再取込分を含む）が対象で、`excel-datano:`で始まるExcel由来の記録と入力途中は除外します。
  対戦日の開始・終了で絞り込めます。省略した側は制限せず、日付の古い順、同日は保存済みの並びで出力します。
  ファイル名は `dac-yyyymmdd-hhmm.csv`（出力時の端末の年月日・時分）です。例：`dac-20261117-1912.csv`。
  CSVをExcelで開き、見出しを除いた25列をコピーし、Ｄシートの追記先A列から「値」として貼り付けます。Z列以降には貼り付けません。
  J列はCN追加メモ、K列は追加メモ、W列は全角化した相手名、X列は仮No.（ない旧記録は空欄）、Y列は日時（YYYY/MM/DD HH:mm:ss、時刻不明は日付のみ）です。
  相手名の入力開始またはViewer情報の貼付・反映時に、端末のローカル時刻を取得します。同じ下書きで名前や店舗を修正しても時刻を維持し、次の対戦では新たに取得します。
  時刻は下書き・JSONバックアップに保持します。未取得の場合は対戦保存時に取得します。過去記録へ保存時刻を後付けしません。
  取得日と入力した対戦日が異なる場合は画面に案内し、日付のみ出力します。ラウンド判定・期間指定・仮No.の採番は従来の日付で処理します。
  記録表には取得済みの時刻も表示します。Excelで時刻を見るにはY列の表示形式を `yyyy/mm/dd hh:mm:ss` にしてください。
  N列は選択権ありで1、O列はランダムでR、Q列は夜で「夜」、R列は勝ちで1、それ以外は空欄です。
  勝率転記・正式Data_No.・シーズン・ラウンド・カード番号は含みません。UTF-8 BOM付き、CRLF、カンマ・引用符・セル内改行に対応します。
  出力済みフラグは付けません。繰り返し出力にも同じ記録を含むため、ExcelのX列で二重転記を確認してください。仮No.のない旧記録は日付・カード・対戦内容で確認します。
  このCSVはアプリ再取込用CSV v1ではありません。Excelで正式Data_No.を付け、X列の仮No.を残したまま更新版OPPONENT_Masterマクロで再出力して読み込みます。
  アプリで保存した記録は「実績」→「３．対戦相手」→「対戦一覧」の「修正」から編集できます。新規入力中の下書き、仮No.、元の対戦時刻は変更しません。日付変更後、対戦時刻の日付が一致しない場合はCSVに日付だけを出力します。
  修正後のCSVには修正内容が含まれますが、Excelへの変更は自動反映されません。既に転記済みならExcelの該当行も修正し、二重追記しないでください。Excel由来の正式記録はアプリで修正できません。
  更新版マクロはY列の日時から時刻を取得し、AD列の日付と一致することを確認して `opponentConfirmedAt` をJSONへ出力します。Y列に時刻がなければAD列の時刻を利用し、両方不明なら省略します。Excel由来の日時は日本時間（+09:00）として扱います。
  対応版の開発用マクロソースは、各行のExcel過去実績（AK対相手戦数・AL対相手勝数・ARコース戦数・ASコース勝数）と行番号も出力します。実際のマクロを更新し、新しい04マスターを作成して取り込むまでは、この実績は表示できません。
  Excelが日時を数値化すると、ちょうど00:00:00の値と時刻不明の日付は区別できません。その場合は時刻不明として扱い、時刻を補いません。文字列として残った `00:00:00` は保持します。
- 集計後CSV v1：保存済みの全対戦を、アプリ再取込用の専用CSVとしてダウンロードします。現在の入力途中・設定は含みません。ExcelのA～Y列への貼り付け用ではありません。
- JSONバックアップ：通常時の退避用です。端末内の保存完了を待って、対戦、入力中の下書き、マスターやオンライン対象などの設定、旧設定の編集下書きを保存します。
- 画面内データの救出用JSON：保存エラー時の緊急退避用です。端末内の保存完了を待たずに、画面内に残った未保存の内容を含めて、通常のバックアップと同じ形式で書き出します。「JSONバックアップを復元」で復元できます。
- 対戦履歴マスターJSON：正式記録を置き換え、未反映の仮登録と入力途中を保持します。通常の過去記録JSON・CSV v1は従来の追加方式です。
- JSONバックアップの復元：確認後、現在の記録・下書き・設定をバックアップの内容で置き換えます。
- 端末内ストレージの保持リクエスト：ブラウザにサイトデータの自動削除を避けるよう依頼します。
  許可されるとは限らず、ファイル出力・同期・バックアップの代わりにはなりません。
  保持許可だけを取り消す標準APIはありません。解除操作の有無はブラウザによります。
  アプリ内データだけの消去は「３．保守・データ管理」から行えます。ブラウザ側で接続先全体のサイトデータを消すと、同じ接続先のほかのアプリにも影響するため注意してください。

いずれのファイルにも個人情報が含まれる場合があります。保存先や共有に注意してください。

- IndexedDBのトランザクション完了後のみ「端末内保存済み」と表示します。
- 新規対戦の仮No.は対戦日・カードごとに `YYYYMMDD-カード名-001` から連番で付与し、999件を超える保存は拒否します。
  CSVの `temporary_no` 列にも出力し、旧CSVも読み込めます。正式なData_No.はExcel側で付与します。
  仮No.のない旧アプリ記録は変更しません。正式登録への移行はOPPONENT_Masterの仮No.完全一致でのみ行います。
  CSV v1は移行用ではないため、別IDの仮No.付き記録と一致する可能性があるCSVは安全のため取り込みを止めます。
  再取込用CSV v1はExcelのDシートと同じ列配置ではありません。Excel貼り付けには専用のA～Y列CSVを使用します。どちらも自動追記はしません。
  採番は１端末に集約してください。別端末で独立して採番した場合や最新状態を含まないバックアップを別端末に復元した場合は重複を防げません。
  同じ端末で古いバックアップを復元しても、復元前の採番履歴は巻き戻しません。
- 入力ごとに下書きを保存します。保存中のリロード警告は補助です。保存完了前の強制終了に対する完全保証はありません。
- 旧版で訂正途中だった下書きは保持しますが、保存済み記録への上書きはできません。必要に応じてJSONバックアップを保存してから下書きを破棄し、新規入力してください。
- 対戦の保存と次の下書き作成は同一トランザクション。中断後のリロードで二重登録しません。
- 複数タブの上書きはリビジョン照合で拒否します。保存失敗後は救出用JSONを取得し、
  他タブを閉じて再読み込みしてください。救出用JSONは未保存の画面内データを含みます。
- 旧画面で未適用だった設定編集は保持・バックアップしますが、現在の画面では適用できません。
- 同じ端末でもブラウザ・プロファイル・配信元URLが変われば別の保存領域になります。
- サイトデータ削除、プライベートブラウズ終了、ストレージの自動削除、故障にはJSONバックアップが必要です。
- サーバー同期、Excel直接アップロード、最終勝利からの候補自動転記は未実装です。
- 「集計後CSV v1を出力（入力用）」は全対戦をダウンロードします。既存ファイルへの自動追記ではありません。
  v1の列仕様とExcel集計後CSVからの変換方法は [history-import-v1.md](./history-import-v1.md) を参照してください。
  Excelの数式として扱われ得る先頭文字にはアポストロフィを付けます。JSONは元の値を保持します。
- PoCでは全データを一つの状態として保存します。本運用の大量データ・同期には対戦ごとのストア等への移行が必要です。
- Service Workerはこのフォルダーだけを対象とし、既存Viewerには作用しません。
  アプリ更新時はキャッシュ名を更新します。新しい版は旧版のタブをすべて閉じた後に適用されます。

## 保守・データ管理

「設定・バックアップ」→「３．保守・データ管理」に次の機能があります。消去を伴う操作は件数と対象を確認してから実行してください。

- 使用状況：正式記録／アプリ入力記録の件数、対戦情報の下書きの有無、JSON換算サイズ、接続先全体の推定保存容量、アプリ用キャッシュの世代数、保持許可と保存状態を表示します。
- 端末内ストレージの保持をリクエスト：保守・データ管理の「使用状況」で、ブラウザに保存領域の保持をリクエストします。バックアップの代わりにはなりません。
  JSON換算サイズは実際の保存容量やメモリ使用量ではありません。日付・カード等の継続値だけの新規下書きは「なし」と表示します。
- 保存して再読み込み：保存キューの完了を待ち、現在の状態を保存してから再読み込みします。保存失敗・別タブとの競合時は中止してエラーを表示します。
- 不要な旧版キャッシュを整理：`dac-record-poc-v数字` のキャッシュだけが対象です。現在の画面の版と、同じアプリの動作中・更新待ち・インストール中のWorkerが使う版は残します。
  状態照会に非対応の旧Workerや応答しないWorkerがある場合は、安全な消去対象を推測せず中止します。このアプリのタブをすべて閉じて開き直すと新版が適用されます。
- 正式な過去記録だけ消去：`excel-datano:` で始まる記録だけを、既存のマスター完全置換処理で除きます。アプリ入力記録・下書き・設定・貼り付け内容・設定下書きは保持します。
  正式記録に含まれる仮No.も採番履歴へ引き継ぎ、番号の巻き戻りを防ぎます。保存完了前には画面上の記録を消しません。再利用には04のマスターを読み込み直してください。
- 完全初期化：最新JSONバックアップの実ファイル保管と別タブ終了のチェック後、対象件数を示す最終確認を求めます。
  同じアプリの別タブが確認された場合は中止します。アプリの正確なscopeに一致するオフライン登録とアプリ専用キャッシュだけを整理し、その後、記録・下書き・設定・採番履歴を1トランザクションで消去します。
  キャッシュ整理・登録解除は記録の消去と一括トランザクションにはできません。途中で失敗した場合は部分的な整理の可能性を明示し、初期化成功とは表示しません。
  古いタブの書き戻しを拒否するため、IndexedDBには個人データを含まない単調増加の更新番号と初期化マーカーだけを残します。次の起動は空の状態で始まります。
  完了後はこのタブでの操作・保存を停止します。タブを閉じ、再利用時はマスターまたは最新バックアップを読み込んでください。採番履歴も消えるため、同日・同カードの再入力前には既存の仮No.を含むデータを復元してください。
  Excel・ダウンロード済みファイル・ほかのアプリのデータ・ブラウザのストレージ保持許可は変更しません。
- 困ったとき：タブを閉じる手順、保存失敗時の救出、バックアップ復元の案内と、診断情報の表示／コピーを用意します。
  診断情報は版・件数・容量の目安・API対応状況などの許可した項目だけです。対戦内容・名前・店舗・メモ・ファイル名・エラー詳細は含めず、自動送信もしません。コピー非対応時は表示欄から手動コピーできます。

保存データの消去は、OSや他アプリのメモリ解放機能ではありません。動作を止める場合は保存完了を確認してアプリのタブをすべて閉じてください。メモリ回収の時期はブラウザ・OSに依存します。
